## What it is

An AI agent that reads a month of business card transactions and assigns each one to an
accounting category — but only acts on its own when it is confident enough to have earned it.

## The problem it solves

A bookkeeper gets ~300 card transactions a month and sorts every one by hand: *"AMZN Mktp
US*Y7D8K6 — is that office supplies or a laptop?"* It is hours of work, and it is the same work
every month.

The naive fix is to ask an LLM to categorize everything. That fails for a reason worth stating
plainly: **the model is wrong sometimes, and it is often wrong confidently.** A bad entry posted
automatically costs a correcting journal, a reconciliation, and trust — far more than the ten
seconds it would have taken a human to catch it.

## The idea

**Confidence → gate → learn.**

1. Every decision carries a confidence score and a one-line reason.
2. Only decisions above a threshold (0.85) post automatically. Everything else goes to a review
   queue, worst guesses first.
3. When a human corrects one, that correction is remembered forever. Next month that vendor is
   free and instant.

The agent is allowed to be wrong. It is **not** allowed to be wrong *confidently*.

## How it works

```
CSV upload → normalize vendor → check memory → (miss) ask the model → route
                                     │                                  ├── confident → posted
                                     └── hit: free, no model call       └── unsure  → review queue
                                                                                          │
                                                                     human corrects it ───┘
                                                                     → remembered forever
```

A LangGraph agent of **exactly four nodes**. Two details carry the design:

- **Memory comes before the model.** A vendor it has seen is answered from a local lookup with
  no API call at all. This is why it gets cheaper every month.
- **Two safety gates live in code, not in the prompt.** If the model invents an account number
  that doesn't exist, that is caught and queued — no matter how confident it claimed to be. You
  cannot ask a model to police itself.

**Stack:** Python · FastAPI · SQLite · LangGraph · OpenAI (`gpt-5.6-luna`) · React + TypeScript +
Tailwind · Recharts.

## What actually happened when it ran

Two months of synthetic transactions, 120 each, against the live model:

| | month 1 | month 2 |
|---|---|---|
| posted automatically | 83.3% | **92.5%** |
| answered from memory (free) | 41.7% | **72.5%** |
| model calls | 70 | **33** |
| cost | $0.028 | **$0.013** |

**The agent got 51% cheaper per transaction, and more accurate, purely by remembering.**

And on a 100-case benchmark with known-correct answers:

| metric | result |
|---|---|
| accuracy | 99% |
| **auto-precision** (of what it posted alone, how much was right) | **100%** |
| **queue-recall** (of what it got wrong, how much it queued) | **100%** |
| wrong **and** posted automatically | **0** |

It made one mistake in a hundred, and it queued that one for a human. That is the whole thesis
working.

## How to run and test it

No API key needed — the entire demo runs in mock mode at zero cost.

```bash
make install
make dev                      # Windows:  ./make.ps1 dev -Port 8123
```

Open **http://localhost:5173**, then:

1. **Import** → upload `examples/month_01_realistic_seed42.csv`
2. Click **Categorize** → watch the confidence histogram fill
3. **Review queue** → see a low-confidence row and its reason; override one
4. Upload `examples/month_02_realistic_seed43.csv` → **Categorize** again
5. **Metrics** → the memory bend, and your override marked *learned*

### Tests

```bash
make test        # 279 backend + 22 frontend tests. No key, no spend
make eval        # 100-case benchmark + the ≥95% auto-precision gate
make eval-live   # the same benchmark against the real model (~$0.03)
```

The interesting tests are the ones that try to break the claims: one injects a model that
*fails the test if it is called at all*, proving memory hits really are free; another runs an
agent that is confidently wrong about everything, proving the quality gate can actually fail.

## Honest limits

- **Cost figures use a placeholder price.** `gpt-5.6-luna` isn't in the pricing table, so the
  dollar amounts use a fallback rate. The *shape* of the curve is real; the absolute numbers
  need the true per-token price set in `.env` (`SPENDSORT_PRICE_INPUT_PER_1M` / `..._OUTPUT_PER_1M`).
- **All data is synthetic**, generated by a seeded engine in `backend/ledgerfab/`. No real
  financial records are involved anywhere.
- **The UI has been recorded but not hand-tested.** 22 automated render tests cover every
  screen; a human has not clicked through every edge case.
- Single-entity, no receipt OCR, no tax-code mapping, no FX conversion — deliberately out of
  scope.
